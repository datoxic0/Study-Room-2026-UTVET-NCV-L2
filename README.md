## Truth & provenance rules

- Every external link carries a verification date (`2026-09-30`) and class: `official`, `community`, `unreachable`.
- Research lives in `research/`: search log (J9), captures with **sha256** (J2), and `evidence.json` gated by
  `corroborate.py --strict --require-hash` â†’ **PASS, 7/7 claims CORROBORATED** (17/17 evidence hash-provenanced).
- Links that failed from the build network (`nols.gov.za`, `utvet.co.za`) are shown **flagged**, not hidden.

## Commands

```bash
npm run check            # lint + unit tests incl. guide provenance (must exit 0)
npm run lint             # bespoke validator: syntax, DOM ids, URL registry, data sanity, Angel terminology
npm run test             # node:test suite
npm run index-notebooks  # rebuild data/notebooks/index.json from exports
npm run ingest-sources   # rebuild data/notebooks/*.sources.txt from hashed source captures
npm run extract-papers   # regenerate js/data/paper_shelf.js from the 17 hashed captures (deterministic)
npm run serve            # local server at http://localhost:8080
```

## Mobile UX & modal scrolling (2026-10-01)

- **Bug proven first, then fixed**: at 390px both readers were unusable — 3723px / 3831px of content inside 776px `overflow: hidden` shells with no scroll path (layout `overflow: visible`, main `max-height: none`) left ~90% of every guide and paper unreachable on phones, while the page behind stayed scrollable.
- Restructured both readers: the topbar is now a direct child of the dialog layout (`js/ui/guides.js`, `js/ui/paper_reader.js`) — a pinned grid row in the right column on desktop, a sticky header of the single scroll area on mobile, so **Close is always on screen**.
- Phone/tablet (≤850px): dialog = fixed-height flex shell capped at `92dvh` (no mobile URL-bar jump; desktop caps upgraded to `dvh` too), layout = **one** scroll area (`overflow-y: auto` + `overscroll-behavior: contain` + `-webkit-overflow-scrolling: touch`), side/main lose nested scrollers, and `body:has(dialog[open]) { overflow: hidden }` locks the page behind the backdrop.
- Touch: every control ≥44px at ≤850px (Close, Reveal/Hide, filter chips, "Show memo answer" summaries); phone reading sizes (13px question/memo text) at ≤600px; `input/select/textarea { font-size: 16px }` stops iOS focus-zoom; `.paper-verbatim` contained (`overscroll-behavior: contain`).
- **Real-device follow-up (2026-10-01)**: the fix passed headless probes but a phone still scrolled the page behind the modal — root cause was the **service worker serving pre-fix cached assets** (Phase 12 changed `styles.css`/`guides.js`/`paper_reader.js` under cache `studyroom-shell-v5` without a version bump, so any client that had visited since the math phase kept the old broken modal). Fixed: cache bumped to `studyroom-shell-v6`, fetch handler switched to **stale-while-revalidate** (cache hits still re-fetch in the background, so a missed bump can never strand a client), new JS body-lock `js/core/dialog_lock.js` synced on both dialogs' open/close (covers engines without `:has()` and open/close races), and `scrollbar-gutter: stable` on `html` so locking the scrollbar cannot shift desktop layout.
- Verified with **real touch gestures** (CDP `Input.dispatchTouchEvent`): drags inside the modal scroll it (`scrollTop 0→285`) while `window.scrollY` stays `0`; drags on the backdrop leave the page locked; SW lifecycle probe on a fresh profile: v6 activates with 23/23 shell files (incl. `dialog_lock.js`), page is SW-controlled after reload and serves the new CSS.
- Verified: mobile CDP probe at **390×844 and 768×1024** — `clipped: false`, scroller reaches the bottom (last element visible), Close on-screen at scroll bottom, `bodyOverflow: hidden`, `tapTargets: []`, no horizontal overflow, 0 page exceptions; desktop sweeps unchanged (30 cards, 7/7 guide modals, reveal 23/23, 0 page exceptions); `npm run check` **39/39**.
- Known data limitation (deliberately not "fixed"): two memos carry Private-Use-Area chars (`U+F050`, `U+F0B2`) from the source PDF's symbol font — no Unicode mapping survived extraction, so they render as tofu; guessing glyph meanings would violate strict-truth. Honest fix = re-extraction with font cmap/OCR (skill v0.3 territory).
